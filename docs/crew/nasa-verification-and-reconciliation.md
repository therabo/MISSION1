## Design recorded before implementation — 2026-10-03

Implemented source observations → identity resolution → reconciliation → canonical interpretation remain distinct. CrewAssignment != StationPresence; LL2 in_space != currentlyAboardIss.

Use the official, advertised https://www.nasa.gov/blogs/spacestation/feed/ RSS feed. It provides bounded recent items, full content:encoded HTML, stable GUID/link and RFC822 pubDate. No article GET, search engine, external redirect, NLP or historical crawl. Bootstrap is the at-most-ten feed items within fourteen days; later feeds are checked for changes to bounded content (not only a publication watermark, since edits matter). A persisted content hash and HTTP validators are the cursor. A gap outside the bounded window yields stale/unknown presence, never assumed continuity.

Parse XML with external entities disabled, then DOM paragraphs with jsoup. Only validated explicit completed entry/departure, already/currently-aboard and count clauses yield evidence. Planned clauses yield no completed event. Candidate presence articles without recognized semantic anchors fail closed. All person lists are PARTIAL: no negative omission rule is enabled for live NASA sources. Count assertions are COUNT_ONLY. The current expedition is discovered by the existing LL2 active-expedition query; NASA expedition mentions remain contextual source text, without a separate membership parser; structured current expedition remains the latest LL2 observation. No mutable NASA mission URL is hardcoded or fetched.

Persist exact deduplicated feed bodies, immutable documents, versioned evidence and subjects. Reuse crew_source_sync_run, adding a verification document foreign key and a source-specific success check; LL2 success continues requiring its snapshot. An unchanged 200 or 304 records another fetch with the same document/evidence. Evidence preserves article URL, pubDate, independently nullable event time, supporting assertion, completeness and parser version. Raw body BYTEA uses PostgreSQL TOAST; one bounded feed body per distinct hash, not one per tick. Malformed captures remain documents but are never usable successful verification.

Resolve using existing external mappings, proven official NASA /people/ profile keys, already persisted cross-source mappings, then conservative exact unique names over all latest known person observations. An ambiguous stronger key prevents weaker fallback. Never transliterate. New validated NASA profile keys may allocate an existing person anchor without fabricating an LL2 profile/assignment. Resolution is a separate immutable audit; unresolved subjects remain queryable and can receive a new audited resolution later.

Reconcile the latest successful LL2 input and applicable persisted NASA evidence as of one Clock instant. Record exact document/evidence/resolution inputs and algorithm version. Relational person states and input FKs accompany an immutable derived snapshot. Runs record success/failure and can reuse identical derived state. Status/quality changes with time are new evaluations; prior snapshots remain unchanged. Queries recompute effective freshness at read time to avoid serving an old snapshot as fresh.

Current-assertion/count applicability is 72 hours from publication; completed event implications require a successful feed check within six hours and event publication within fourteen days. Membership never establishes presence. LL2 structured retrieval freshness is six hours. These configurable thresholds are conservative MISSION1 policy, not NASA cadence/accuracy guarantees. Exact event time orders completed events when explicitly available; otherwise publication is a weaker assertion context. Retrieval time is never an event instant. Conflicting equally timed claims become ambiguous. Future/planned evidence does not alter current state. Exhaustive negative inference is supported only for an explicitly classified exhaustive roster and prior known presence; no live source is classified exhaustive in this milestone.

Scheduling uses existing Spring machinery: enabled by default, PT2H fixed delay, PT10M initial delay (after LL2 PT5M), process-local overlap guard, durable eligibility/Retry-After, no retries. Reconciliation consumes persisted inputs through a composition-level coordinator; source schedulers never call each other's network. Incomplete crash runs remain observable; generic abandonment is deferred because a guessed timeout could misclassify an active run.

Scope ends at internal queries. Crew REST/UI, notifications, event-aware refresh and Replay remain future. Orbit, graphics, accepted LL2 schema/history and request budget remain frozen.

## Runtime source and deterministic discovery

The only automated NASA source is the official [Space Station RSS feed](https://www.nasa.gov/blogs/spacestation/feed/), advertised by the [Space Station blog](https://www.nasa.gov/blogs/spacestation/). The stable feed URL is configuration-independent verified provider infrastructure; dated article links come from item/link and never application constants. RSS full content supplies current positive roster fragments and completed events; there is no exhaustive current-roster source in the selected integration. Structured current expedition discovery remains LL2's active-expedition query. The [station overview](https://www.nasa.gov/international-space-station/) and linked [expedition directory](https://www.nasa.gov/international-space-station/expedition-missions-content-list/) were investigated, but mixed editorial rosters/date-only updates do not provide a dependable exhaustive, time-qualified current roster. The exposed WordPress API was inspected for discovery only; it is not polled. Visiting-vehicle pages are not current-person occupancy authority and are not acquired in this milestone.

Normal cycle: one RSS GET, no article/profile/mission-page GETs and no retry. At most ten feed items and fourteen days of publications are parsed. Full older history is not crawled on bootstrap. Failed transport has no usable evidence. A valid feed with no presence assertion means no new knowledge, never zero people. Retained database evidence stays available for temporal ordering and stale last-known interpretation; current history reads are two batch reads over retained assertions, not an indefinitely paginated provider crawl. Database read cost grows with retained assertions; no automatic retention or historical compaction is implemented.

## Actual parsers and failure contract

| Parser | Version | Required anchors and output |
| --- | --- | --- |
| NasaOperationalFeedParser | 1.0.0 | Secure RSS XML, one channel with the exact verified ISS title, 1–10 items, distinct GUIDs, official HTTPS NASA article link, valid RFC1123 pubDate, one full content:encoded section. XML entities/DTDs are disabled. Items beyond the bootstrap window are ignored. |
| NasaOperationalPostParser | 1.0.0 | DOM paragraphs, explicit agency/person-list grammar, completed “have entered”/“have departed”, existing crew “already aboard”, separate “bring the number … to N”. Named clauses must parse completely. |

Both are code-versioned. Recognized transition articles lacking required anchors invalidate the capture as MALFORMED_RESPONSE; unrelated additional markup is ignored. Planned clauses are skipped. A completed crew-mission undocking without explicit individual departure subjects fails closed: no Crew-N→person inference. This deliberate limitation requires a new validated parser version before automatic handling of other editorial grammars. Synthetic tests for the explicit named-departure grammar are not a claim that every NASA departure article uses it.

The recorded entry paragraph also emits HATCH_OPENED with EVENT_ONLY completeness. Its clock text remains in the supporting excerpt. Both hatch and individual event timestamps remain null where the source paragraph lacks an independently explicit absolute date; publication time supplies the weaker assertion context. The parser never substitutes hatch time for personal entry time. Locally decoding the observed Outlook Safe Links url parameter adds no network calls; only a NASA /people/ link whose anchor names the subject becomes a profile key. Two NASA-only profile pages were also validated live as single-person pages. No runtime profile crawl is introduced.

## Identity and field authority

`CrewPersonResolver/crew-person-resolution-v1` checks existing NASA external mappings (including canonical profile keys), then a matching validated NASA profile among known identities, then a conservative unique exact name across latest stored person observations. Case, whitespace, NFC and punctuation normalization are allowed; accent folding, transliteration, reordered tokens, initials expansion and fuzzy matching are forbidden. A distinct stronger key or multiple candidates produces AMBIGUOUS and blocks weaker fallback. A validated unknown official profile can allocate a NASA-only UUID anchor; it creates no LL2 profile or assignment. Without an ID/profile and without a unique exact candidate, the subject stays UNRESOLVED. `AUTHORITATIVE_MAPPING` is reserved audit vocabulary; no manually invented mapping table or current-person exception is configured. Existing mappings are immutable and reviewed resolution decisions are retained, rechecked against new candidates and reused only while the decision still holds.

LL2 owns source profile fields and structured expedition assignments. NASA owns its explicit, time-qualified presence and count assertions. Reconciliation owns the derived interpretation. NASA cannot overwrite LL2 biography, career, agency, nationality, media or roles. A present NASA-only UUID can therefore lack a structured profile. Same-name fallback is an audited narrow decision, not a universal identity proof. Unresolved spelling variants remain visible.

## Canonical states and implemented status order

Each person carries its MISSION1 UUID, current presence, last-known interpretation, assertion context, evidence IDs and independent LL2 assignment flag. `CONFIRMED_ABOARD` requires a usable positive NASA assertion; `CONFIRMED_NOT_ABOARD` requires a usable completed named departure or a later fully resolved exhaustive roster omitting a previously evidenced person. `UNVERIFIED` covers structured assignments without usable verification, `UNKNOWN` covers absence of a usable assertion, `STALE` retains last-known state after applicability expires, and `AMBIGUOUS` retains conflicting equal-time assertions. Counts remain separate; missing count is null. A later completed transition invalidates an older count even when that transition's subject cannot be resolved. No arithmetic roster/person fabrication occurs.

`CrewReconciliationEngine/crew-reconciliation-v1` evaluates these statuses in precedence order:

| Status | Implemented condition |
| --- | --- |
| AMBIGUOUS | Ambiguous identity, conflicting equally timed person claims/counts, or official count below the number of confirmed resolved people. |
| VERIFICATION_UNAVAILABLE | No successful NASA capture, latest actual NASA failure, or no usable presence/count evidence. Retained LL2 and NASA history remain accessible. |
| STALE | Retained relevant assertions/count or latest successful NASA check exceed policy; after verification passes, an aged LL2 structured fetch also produces STALE. |
| PRIMARY_UNAVAILABLE | NASA evidence is usable but no successful LL2 input or a newer actual LL2 failure exists. NASA person state can remain usable without complete profiles. |
| MATCH | Fresh comparable EXHAUSTIVE roster, identical resolved sets, no unresolved subjects, and compatible count if supplied. Partial/count-only equality cannot reach MATCH. |
| NASA_AHEAD | NASA-only confirmed people all have a fresh completed entry newer than the latest LL2 successful retrieval, with no unresolved subjects. A count difference alone is insufficient. |
| LL2_AHEAD | Fresh comparable exhaustive roster, no NASA-only/unresolved subjects, and every LL2-only assignment has explicit validFrom newer than the latest exhaustive roster context. |
| PARTIAL_MATCH | Remaining usable but incomplete comparisons. This is the observed live result, not a declaration of exhaustive agreement. |

Event time orders assertions when explicitly supplied; otherwise publication orders weaker contexts. Retrieval controls knowledge availability/fetch freshness, never event order. Future/planned claims cannot change current presence or count. Later unrelated articles do not supersede a person's claim; later per-person statements do. Equal-time contradictory statements stay ambiguous. Exhaustive omission requires all roster identities resolved and prior positive evidence. No live parser emits EXHAUSTIVE.

Default policy: primary retrieval PT6H, NASA successful check PT6H, roster/count publication PT72H, completed-event current implication P14D. Historic event validity is preserved after these limits. Policy values are configurable and included with `crew-freshness-v1` in the algorithm key, so a policy change produces new interpretation history.

## Persistence, operational health and query boundary

Flyway [V4](../../backend/src/main/resources/db/migration/V4__crew_nasa_verification_and_reconciliation.sql) adds twelve Crew tables, retaining V1–V3 checksums. `crew_document_body` deduplicates exact bounded bytes by SHA-256; documents deduplicate URL/hash/parser version. Semantic evidence deduplicates independently of container retrieval/hash, with document→evidence associations retaining subsequent feed captures. Immutable subject rows preserve original names/profile links. Each identity-resolution audit includes evidence/subject, method, candidates/key and resolver version. Reconciliation snapshots retain input run/snapshot/evidence/resolution IDs, first computation time, algorithm/policy key and relational person states. Restrictive FKs and update/delete rejection protect all source/derived graphs; no destructive cascades were added.

A fetch attempt is a `crew_source_sync_run`, even for unchanged 200, 304, skip or failure. A reconciliation attempt is a `crew_reconciliation_run`; identical input interpretation reuses one snapshot while each run records its completion. Run IDs/latest fetch timestamps are omitted from the interpretation dedupe key. The immutable snapshot therefore preserves its first computation/input context; latest operations are exposed separately. Document/evidence/parse completion commit atomically; failed writes roll back before the operational failure is recorded in a separate transaction. Derived graph failure preserves the previous snapshot.

`CrewReconciliationQueryService.current()` evaluates effective age read-only using persisted resolutions, returns the structured LL2 snapshot/profiles, current interpretation, each source's attempt/success/failure/Retry-After, last malformed-document parse, last reconciliation attempt and retained successful derived snapshot. It performs no provider requests or resolution writes. The public read-only Crew controller now adapts this query as documented below.

Independent root schedulers coordinate post-attempt reconciliation over persisted inputs. LL2 never calls NASA HTTP and NASA never calls LL2 HTTP. Manual internal callers can ingest then invoke reconciliation explicitly. Skips do not create derived runs; successful unchanged fetches can reevaluate freshness while deduplicating state. Defaults NASA enabled, PT2H fixed delay (minimum PT1H), PT10M initial delay (minimum PT6M), LL2 defaults unchanged. Conditional validators come from a prior successfully parsed document of the same parser version. Retry-After and actual-attempt eligibility survive restart; overlap protection is process-local. Generic abandoned-run recovery remains deferred: elapsed time alone cannot distinguish an active request from a crashed process without ownership/liveness semantics. IN_PROGRESS stays visible, and ordinary age-based query degradation still works.

404/429/5xx/timeouts/network/invalid content/required-anchor failure do not replace prior successful evidence or invent an empty roster. Latest actual failure degrades verification. Ambiguity remains a derived result. Persistence/reconciliation failures are isolated and recorded when PostgreSQL is available; a total database outage can leave an unfinished run. One backend and PostgreSQL remain sufficient. See the [dated validation dossier](reconciliation-validation/README.md) for actual IDs, timings and limitations.

The internal canonical query also returns the exact typed NASA evidence and identity audits used by its interpretation (including NASA-only display names/profile links and article timestamps). Structured LL2 data is read by the interpretation’s exact snapshot/run IDs, preventing a concurrent ingestion from mixing a newer structured snapshot with an older interpretation. No source parsing or identity inference is required in future REST.

A persistence failure preserves the actual parser/source state separately from the failed operation. In particular, an AVAILABLE parsed NASA document followed by a database rollback records PERSISTENCE_FAILURE with source state AVAILABLE, not a false MALFORMED_RESPONSE. No successful evidence is committed; effective verification still degrades through the failed operational run.

## REST exposure — 2026-10-03

The [implemented Crew API](../api/crew-api.md) adapts the existing canonical query; all source/parser/identity/algorithm/freshness semantics remain unchanged. Public fields include resolved presence/last-known/as-of/evidence, exact eight reconciliation statuses/algorithm/evaluation time, persisted computation and latest reconciliation-operation times, source-specific success/attempt/failure/rate-limit/freshness, separate official/count-gap/assignment quantities and unresolved source assertions. Count applicability only selects current versus retained API fields using the existing policy; no new domain interpretation is written. Public article/feed provenance preserves URL/hash/publication/event/original-retrieval context, while latest successful fetch is separate. GET has zero source calls and zero writes.
