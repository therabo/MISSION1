The 2024 FBX-to-GLB translation conversion `(x,y,z) → (x,z,-y)` has determinant **+1**. It explains the up-axis change but **cannot create** the GLB root's negative determinant. That parity inversion is explicit in the named GLB's root transform. Because the original Blender scene, export settings and a publisher explanation are absent, the choice between an authored reflection and a conversion/presentation step remains unresolved. The 2026 FBX/GLB do not preserve the same root hierarchy, so they cannot settle its origin. No claim about ISS body-frame handedness follows from this export transform.

## Structural frames and usable control points

The public NASA/TM report defines the ISS analysis frame as body fixed at S0, +X forward, +Y starboard and +Z nadir, with S0's origin defined by trunnion-pin base centers (§2.2). SSP 30219 additionally distinguishes a station reference frame with a shifted datum, a center-of-mass body frame, a Russian-segment analysis frame, LVLH and XPOP attitude references, and module-specific frames. Operational attitude frames cannot be substituted for either asset's authoring frame. SSP's use restriction and absent asset mapping prevent its detailed definitions from approving a production transform.

## Russian and iROSA evidence matrix

NASA's reports explicitly give **Service Module nadir → MLM/Nauka → Russian Node Module/Prichal** as the real attachment chain. The 2024/2026 FBX and named GLB contain `MLM` and `Russian_RSNode_DockingModule` as source nodes, with calculable relative object transforms. No source explicitly equates the **asset string** `Russian_RSNode_DockingModule` to Prichal. Five visible docking directions and location support that inference but do not verify identity. The official frame descriptions do not supply the missing asset-node-to-frame matrices.

## Contact path and research gate

The NASA [3D Resources README](https://github.com/nasa/NASA-3D-Resources#readme) publicly lists `arc-special-proj@lists.nasa.gov` for repository feedback. The NASA [IGOAL organization page](https://www.nasa.gov/integrated-graphics-operations-and-analysis-laboratory/) identifies the responsible JSC group but gives no model-specific technical mailbox. The [VTAD resource page](https://science.nasa.gov/resource/international-space-station-3d-model/) credits VTAD but gives no model-specific technical contact. **No contact was made.** A minimal request to the asset maintainers would ask for (1) the original Blender scene/export notes and physical units; (2) each asset's root-to-ISS structural frame matrix and origin; (3) an explicit RSNode→Prichal mapping; and (4) labeled CBM, SM/MLM/Node docking and six mast-canister mount-frame transforms or interface centers.

The new material defines candidate physical controls and corroborates all six iROSA parents, but **does not map a reproducible control point into both assets or independently constrain the cross-asset scale/origin**. Numerical registration was therefore **not rerun**. The next evidence gate remains a publisher-provided asset-frame/interface contract. No geometry composition or visual tuning was performed.
