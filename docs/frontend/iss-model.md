# ISS model asset and presentation record

Selection gate: **`MODEL_READY_FOR_INTEGRATION`**. This record covers the first detailed station geometry in the Cesium Earth View. It does not establish a current ISS configuration, onboard position measurement, station attitude, or moving hardware state.

The [current-geometry assessment](iss-current-geometry-assessment.md) (2026-09-30) compares official VTAD and NASA/JSC IGOAL files, modern component coverage and exact-transform feasibility. Its selected strategy is `KEEP_CURRENT_VTAD`; this production geometry and its semantic derivative have **not** been updated to a current station configuration.

The selected [NASA VTAD resource](https://science.nasa.gov/resource/international-space-station-3d-model/) is dated **22 April 2019**; NASA lists the downloadable model update as **9 September 2023**. That download date does not demonstrate a new station configuration. The GLB visibly contains a node named `13 Pirs Docking Compartment (DC) and Airlock`. [Pirs undocked in July 2021](https://www.nasa.gov/blogs/spacestation/2021/07/26/progress-77-and-pirs-undocked-from-station/) and [Nauka docked later that month](https://www.nasa.gov/blogs/spacestation/2021/07/29/new-module-successfully-docks-to-space-station/). Nauka and later [roll-out solar arrays](https://www.nasa.gov/international-space-station/international-space-station-assembly-elements/) are not identifiable in this asset. Visiting vehicles and other later changes also cannot be assumed. The asset is a documented historical visual reference, **not an exact 2026 ISS configuration**. No hardware was invented or added.

## Runtime derivative and validation

The original VTAD GLB is available from the NASA resource page at [NASA's direct `ISS_stationary.glb` URL](https://assets.science.nasa.gov/content/dam/science/psd/solar/2023/09/i/ISS_stationary.glb). The current runtime file is [`frontend/public/models/iss-vtad-source-png.glb`](../../frontend/public/models/iss-vtad-source-png.glb), **32,735,516 B**, SHA-256 `ce23515c6bf4a77d3bac6b7c2554e3c92e137c11c8db3ee1ffc1f3ef2030a16f`. Its NASA source hash and runtime revision are pinned in [`issModelManifest.json`](../../frontend/src/cesium/issModelManifest.json). The original 44.5 MB file is intentionally outside the repository. No Git LFS or runtime NASA request is needed.

Reproduce the derivative with glTF Transform CLI **4.5.1**, using its normal CLI installation from npm and the direct GLB download exposed on the NASA page:

```sh
gltf-transform dedup ISS_stationary.glb iss-dedup-png.glb
shasum -a 256 ISS_stationary.glb iss-dedup-png.glb
python3 frontend/scripts/add-verified-module-features.py iss-dedup-png.glb frontend/public/models/iss-vtad-source-png.glb
shasum -a 256 frontend/public/models/iss-vtad-source-png.glb
```

The 32,197,496 B deduplicated PNG base derivative has SHA-256 `ce2548b56741ee764de7e1d593f1c50785a54150ebc500ed5424a4f5bdf8f657` and is the strictly pinned input to the feature-metadata script. The current runtime file retains **132 nodes, 131 meshes, 343 primitives, 325,374 vertices, 247,547 triangles and the original bounds**, with 19 embedded lossless PNG images after deduplication. The original GLB has 26 PNG entries, 19 unique images, all 512² or 1024²; the deduplicated source preserves their pixels. Four authored materials include normal maps and all source alpha channels are opaque. The script appends metadata and one sampler policy without editing geometry, materials, node transforms or texture bytes. It uses `EXT_mesh_features` and `EXT_structural_metadata`, which [CesiumJS supports](https://cesium.com/learn/cesiumjs/ref-doc/Model.html). The sampler requests linear magnification and trilinear minification with mipmaps; the GLB does not embed a precomputed mip chain. The runtime GLB file is about 32.7 MB, **not measured GPU memory**; decompressed textures, mip levels and draw resources add memory.

The original NASA file passed Khronos **glTF Validator 2.0.0-dev.3.10** with **0 errors, 17 warnings and 37 informational messages**. The PNG semantic derivative passed with **0 structural errors** under glTF Transform CLI 4.5.1 validation on 2026-09-29; pre-existing tangent-space and degenerate-triangle warnings remain. This validator reports the two feature extensions as unsupported for extension-specific validation; Cesium 1.145 browser picking is checked separately. No geometry was rebuilt. Production build must contain the GLB at `dist/models/iss-vtad-source-png.glb` with the manifest hash.

## Scale, axes and presentation semantics

[NASA describes the ISS as about 109 m across its solar arrays](https://www.nasa.gov/reference/international-space-station/). The asset's longest measured bounding dimension is **111.988 model units**, 2.99 m or **2.74%** above that approximate NASA span. [glTF 2.0 defines linear distances in meters](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc); the bounds are consistent with a meter-authored station. `PHYSICAL_ASSET_SCALE = 1.0` preserves that dimensional validation. The difference can include bounding-box orientation and model extent; it is not treated as an orbital or hardware measurement.

Earth View uses `DISPLAY_ENHANCED_SCALE`: **the rendered ISS is NOT TO SCALE**. Cesium `Model.minimumPixelSize = 80` aims to keep the silhouette legible as the camera retreats, while `Model.maximumScale = 20000` bounds enlargement to at most 20,000 times the 1.0 physical asset scale. These are presentation parameters, not physical dimensions. At close distance, the minimum pixel rule ceases to enlarge the model. At medium distance it increases apparent size toward 80 pixels; at global distance the upper scale bound may prevent reaching 80 pixels. The sampled WGS84 position, altitude, and orbital path do not change. [Cesium documents both sizing controls and their relationship](https://cesium.com/learn/cesiumjs/ref-doc/Model.html).

Cesium converts the asset's glTF axes for rendering, then builds its ENU frame with `Transforms.eastNorthUpToFixedFrame`. The explicit static `MODEL_ASSET_ALIGNMENT` is **identity**. Existing asset-centering translation places the off-origin bounds at the model display point. In Earth Overview this point is the selected physical ITRF position plus a **75 km display-only WGS84-normal lift**. Lift smoothly reaches zero in the first 1.75 seconds of entry; in Inspection the model center and camera pivot use the true selected physical position. The camera target, reported altitude and trajectories never inherit the display lift. Back restores it smoothly over 1.2 seconds. This does not shift the orbital coordinate. The resulting pose is **`DISPLAY_ONLY_LOCAL_ENU`**. `ATTITUDE = UNAVAILABLE`: no verified station attitude source or frame convention is present. The model is not aligned to orbital velocity, LVLH or the Sun. Solar-array nodes keep the source asset pose and are not animated.

The physical locator, readout, approach and pivot evaluate one selected bounded `SampledPositionProperty(ReferenceFrame.FIXED)`: the mandatory primary short buffer or the independent covered NASA OEM property. Each tick evaluates that source at the same scene time. Only the model matrix applies the separate display lift; no second propagation, invented orbit or attitude path exists. The model remains visible at valid camera distances once ready. The ready model is the only visible ISS representation at all valid camera ranges. A temporary point and `ISS` label appear only while the model is loading or has failed. Model loading, readiness and failure are independent of orbital delivery; an expired sample window hides both. [ISS Inspection Mode](iss-inspection-mode.md) now uses a progressive world-space approach before the moving ENU camera pivot. The display-enhanced model grows along that camera path while the backend orbital coordinates and physical asset scale remain unchanged. Its close zoom factor is **0.01**; Earth Overview restores 5.

Earlier browser checks at 843 × 885 on 2026-09-29 compared `maximumScale` values 5,000, 15,000 and 20,000, and `minimumPixelSize` values 48 and 72. With the final 72/20,000 setting, the global model remained a distinct roughly 50-pixel ISS silhouette on a roughly 410-pixel Earth disk, without obscuring a broad region. In a regional/orbital view it remained identifiable at roughly 50–60 pixels. The inspection approach now passes through a 60 km station vicinity before arriving at 340 m, with bounded display size; camera motion never changes the sampled orbital state. These are visual checks, not physical measurements or a pixel-accuracy contract.

## Hierarchy and semantic mapping

The full machine-readable [`iss-model-inventory.json`](iss-model-inventory.json) records each node index, exact source name, parent, mesh name and materials. The runtime GLB itself is the geometry source. The manifest pins the runtime hash so mapped indices cannot silently point into a different file.

The complete [semantic map](iss-semantic-map.md) records the evidence method and all 14 `VERIFIED` components, including 11 additions. The [machine-readable review](iss-semantic-review.json) classifies **all 132 named nodes**: 44 clear candidates, 48 ambiguous names, 38 generic geometry nodes, and 2 technical nodes. These are investigation classes, not identity verification. **118 nodes remain `UNMAPPED`**; there are no `PARTIALLY_VERIFIED` mappings. `VERIFIED` asset identity and current configuration are independent. Pirs is verified geometry but was removed in July 2021. Dated 2026 reports support current status for the other selected components; this does not make the entire VTAD geometry a 2026 configuration. The manifest holds the runtime identity and configuration evidence URLs, dates, type, agency, and role.

### Picking investigation and selected approach

**Original untagged asset classification: `ENTITY_ONLY_PICKING`. Strategy: `DIRECT_FEATURE_PICKING`.** The previous pinned WebP base GLB had no `EXT_mesh_features`, `EXT_structural_metadata`, or feature IDs. A temporary probe on the actual Cesium 1.145 Earth View called `Scene.pick` on the visible NASA model. Geometry hits returned a plain pick object with `id: "ISS_MODEL_PICK_PROBE"`; empty-space clicks returned `undefined`. Hits had no public glTF node name, mesh identity or feature ID. [`Model.getNode(name)`](https://cesium.com/learn/cesiumjs/ref-doc/Model.html) gives programmatic node access, not screen-space node picking. [`Scene.pick`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html) and [`ModelFeature`](https://cesium.com/learn/cesiumjs/ref-doc/ModelFeature.html) provide the public screen-space path once feature metadata is present. Private Cesium fields are not used by production selection.

The reproducible script [`add-verified-module-features.py`](../../frontend/scripts/add-verified-module-features.py), revision 2 (manifest-driven), reads only `VERIFIED` entries from the runtime manifest. It preserves Destiny/Columbus/Harmony feature IDs **0/1/2** and appends IDs **3–13**. Each tagged mesh has one owning node; only direct primitives are tagged. Descendants are excluded, so a parent node cannot claim a different named component. All other primitives remain untagged. `EXT_mesh_features` stores `_FEATURE_ID_0` per vertex; `EXT_structural_metadata` stores a 14-row `moduleCode` property table. Tests check every tagged accessor and exact tagged-node set. [Feature IDs](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_mesh_features) and [structural metadata](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_structural_metadata) are extension specifications.

`Scene.pick` and `Model.getNode` are documented public APIs. `Model.featureIdLabel` and `ModelFeature.featureId` are also documented public APIs, but Cesium marks their 3D Tiles feature-metadata behavior **experimental** and subject to change without its normal deprecation policy. The project pins Cesium **1.145.0**, tests the exact GLB revision and verifies picking in the browser; a Cesium upgrade must repeat that check. No undocumented/private pick fields are used.

The original three-feature derivative was browser-verified with `ModelFeature` IDs **0/1/2** and `moduleCode` values **1/2/3**. The expanded derivative preserves those values and adds 11 direct feature identities. Untagged station geometry returned the plain model pick object or no hit and never resolved to a verified module. Production `Model.fromGltfAsync` sets `featureIdLabel: "missionModule"` and `enablePick: true`; the click handler uses only public `Scene.pick`, `ModelFeature.featureId`, and `ModelFeature.getProperty`. It requires both ID and code to match the pinned manifest. Module selection is enabled only within **1,000 m** camera-to-sampled-center distance, where the geometry is inspectable; global distance selects no module. Feature picking uses the same rendered Cesium model and therefore remains aligned with its `minimumPixelSize`/`maximumScale` display enhancement without a separate pick proxy or orbital coordinate calculation. Occluded module surfaces or very small visible facets may yield no selection; they never fall back to guessed spatial association. A click on empty or unmapped geometry clears the panel.

The pre-inspection production preview was tested in-browser at 1280 × 720. At the former close focus and at a slightly wider view, direct clicks selected all three original modules. Clicks on a solar array, truss, another unmapped part and empty space left no module selected. Earth overview cleared a previous selection. A closer test found some facets returned no feature because foreground unmapped geometry or gaps occupied those pixels; there was no incorrect verified selection. Module picking is intentionally surface-specific and may require a clear view of the named mesh.

### Expanded browser acceptance, 2026-09-29

In the development browser, actual clicks on visible representative geometry selected **all 14 verified identities** across multiple camera angles. This includes the 11 new identities, the original Destiny/Columbus/Harmony identities, and the small Cupola and historical Pirs surfaces. The Pirs panel visibly reported **Removed from current station**, linked its July 2021 removal evidence, and kept live module telemetry **unavailable**. Solar-array, truss, generic unmapped and empty clicks produced no verified component. In the served production build, direct clicks also selected **all 14 identities** across multiple camera angles, including Pirs and [Cupola](iss-semantic-production-cupola.jpg). The production GLB hash matched the tested runtime hash.

Both browser builds retained the moving ISS pivot during mouse orbit and inward/outward wheel zoom. A longer drag exposed a camera excursion in the development browser; the corrected inspection update bounds its local range at 2,000 m. Retesting the same drag kept the camera at 340 m and the ISS centered. Outward zoom increased measured range from 340 m to approximately 411 m without switching to an Earth-centered pivot. **Back to Earth View** restored the overview camera, path and locator, and repeat entry worked. The available browser control did not expose a meaningful touch orbit or pinch gesture, so touch behavior remains unverified. A production tab briefly showed a Cesium render error while its local backend and preview servers were stopped between sessions; reloading after restart restored a ready model and active orbital buffer, with no new render error observed. The browser used a real stored CelesTrak element set that the UI correctly marked `STALE`; it did not substitute synthetic orbital values.

The source-PNG quality pass kept the same NASA mesh/node structure and regenerated all 14 direct feature IDs. Automated GLB checks assert every tagged primitive, per-vertex ID, property-table code, node name and preserved configuration mapping. The final served-production browser regression clicked visible tagged geometry for **all 14 verified identities** across several camera angles. Each `Scene.pick` returned the expected `ModelFeature` ID and `moduleCode`, and each click opened the matching information panel: Destiny, Columbus, Harmony, Pirs, Poisk, Zvezda, Rassvet, Zarya, Kibo Exposed Facility, Kibo Pressurized Module, Quest, Cupola, Tranquility and Unity. Pirs remained explicitly marked as removed from the current station. Solar-array, truss, generic unmapped geometry and empty-space clicks did not resolve a verified identity or leave a module panel open. **14/14 VERIFIED production picks passed.**

The generic panel shows verified name and ID, type, agency and role where evidenced, separate mapping and configuration status, source links, historical-configuration caveat, `NOT TO SCALE` display notice, and **“Live module telemetry: unavailable”**. Selection issues no module/API request. The panel does not treat static asset naming as current onboard telemetry.

## Local performance observations

The previous 15,713,052 B semantic WebP file used quality-90 lossy versions of the same 19 textures. Measured RGB PSNR against the NASA PNG images was about **40.6–47.2 dB**; source-quality PNG was selected for close inspection. High-quality KTX2/UASTC was evaluated, but the available toolchain lacked `toktx` and no better stable visual result was established. The new semantic GLB is 32,735,516 B. In warm development-browser trials, `Model.fromGltfAsync` to texture-complete `readyEvent` took roughly **0.5–0.8 s**. The first served-production browser load took **3.7 s**, with the marker visible until the model was ready. The model preloads with `incrementallyLoadTextures: false` and `show: false`, checks all 14 named semantic nodes at readiness, then becomes eligible for reveal. One primitive persists across view changes. The locator remains while loading/failure; the 2026-09-30 [orbital presentation refinement](orbital-trajectory-rendering.md) removes it once ready and replaces the earlier distance-threshold policy. No white or missing-texture station frame was seen in approach/inspection trials. These are local observations, not a guarantee for all GPUs or cold networks. The model contains roughly 247,547 triangles; authored PBR materials and scene lighting remain unchanged, with no synthetic station lights. See [rendering quality](rendering-quality.md) for asset and GPU tradeoffs.

The 2026-09-30 trajectory review increased the Overview minimum footprint to 96 px (bounded by the existing maximumScale), verified a visible model without a point at global range, and confirmed served-production model entry and Poisk semantic picking. Historical 48/72 px trials above remain dated evidence, not the current configuration.

The initial selectable milestone used **92 px** with no lift; that visual result was rejected. The subsequent verification-and-fix selected **80 px** and a **75 km model-only display lift**, with no silhouette. Controlled 92/88/84/80 footprint trials and 0/2/5/8/10/25/50/75/100 km lift projections are recorded in the [current evidence](trajectory-fix-review/README.md). Model position remains derived from the selected real bounded product, while physical position and altitude remain explicit and unchanged. See [ADR-0006's dated correction](../adr/0006-selectable-forward-trajectory-visualization.md#presentation-correction--2026-09-30).
