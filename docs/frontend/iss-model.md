# ISS model asset and presentation record

Selection gate: **`MODEL_READY_FOR_INTEGRATION`**. This record covers the first detailed station geometry in the Cesium Earth View. It does not establish a current ISS configuration, onboard position measurement, station attitude, or moving hardware state.

The selected [NASA VTAD resource](https://science.nasa.gov/resource/international-space-station-3d-model/) is dated **22 April 2019**; NASA lists the downloadable model update as **9 September 2023**. That download date does not demonstrate a new station configuration. The GLB visibly contains a node named `13 Pirs Docking Compartment (DC) and Airlock`. [Pirs undocked in July 2021](https://www.nasa.gov/blogs/spacestation/2021/07/26/progress-77-and-pirs-undocked-from-station/) and [Nauka docked later that month](https://www.nasa.gov/blogs/spacestation/2021/07/29/new-module-successfully-docks-to-space-station/). Nauka and later [roll-out solar arrays](https://www.nasa.gov/international-space-station/international-space-station-assembly-elements/) are not identifiable in this asset. Visiting vehicles and other later changes also cannot be assumed. The asset is a documented historical visual reference, **not an exact 2026 ISS configuration**. No hardware was invented or added.

## Runtime derivative and validation

The original VTAD GLB is available from the NASA resource page at [NASA's direct `ISS_stationary.glb` URL](https://assets.science.nasa.gov/content/dam/science/psd/solar/2023/09/i/ISS_stationary.glb). The current runtime file is [`frontend/public/models/iss-vtad-webp.glb`](../../frontend/public/models/iss-vtad-webp.glb), **15,269,472 B**, SHA-256 `c812b8e5e415d7d2867cc68b0ab43b64ad0cbbf4fb95cf0dbdb6cc717ae17aa1`. Its NASA source hash and runtime revision are pinned in [`issModelManifest.json`](../../frontend/src/cesium/issModelManifest.json). The original 44.5 MB file is intentionally outside the repository. No Git LFS or runtime NASA request is needed.

Reproduce the derivative with glTF Transform CLI **4.5.1**, using its normal CLI installation from npm and the direct GLB download exposed on the NASA page:

```sh
gltf-transform dedup ISS_stationary.glb iss-dedup.glb
gltf-transform webp iss-dedup.glb iss-vtad-webp-base.glb --quality 90
shasum -a 256 ISS_stationary.glb iss-vtad-webp-base.glb
python3 frontend/scripts/add-verified-module-features.py iss-vtad-webp-base.glb frontend/public/models/iss-vtad-webp.glb
shasum -a 256 frontend/public/models/iss-vtad-webp.glb
```

The intermediate deduplicated GLB was 32,197,496 B. The 15,175,080 B WebP base derivative has SHA-256 `e5ad5beb2f1ea4364c964f316a072775d8f9d4c4bfed126932aa07a85f438360` and is the strictly pinned input to the feature-metadata script. The current runtime file retains **132 nodes, 131 meshes, 343 primitives, 325,374 vertices, 247,547 triangles and the original bounds**, with 19 embedded images after deduplication. The script appends metadata without editing existing geometry, materials, node transforms or texture bytes. It uses `EXT_texture_webp`, `EXT_mesh_features` and `EXT_structural_metadata`, which [CesiumJS supports](https://cesium.com/learn/cesiumjs/ref-doc/Model.html). The runtime GLB binary buffer is about 15 MB; that is a file payload figure, **not measured GPU memory**. Browser texture decompression and draw resources add memory.

The original NASA and WebP base files passed Khronos **glTF Validator 2.0.0-dev.3.10** with **0 errors, 17 warnings and 37 informational messages**. The semantic derivative passed with **0 errors, 17 warnings and 40 informational messages**. This validator version reports both new feature extensions as unsupported for extension-specific validation; Cesium 1.145 browser picking was verified separately. Existing tangent-space warnings and degenerate triangles were not introduced by this derivative. No geometry was rebuilt. Production build must contain the GLB at `dist/models/iss-vtad-webp.glb` with the manifest hash.

## Scale, axes and presentation semantics

[NASA describes the ISS as about 109 m across its solar arrays](https://www.nasa.gov/reference/international-space-station/). The asset's longest measured bounding dimension is **111.988 model units**, 2.99 m or **2.74%** above that approximate NASA span. [glTF 2.0 defines linear distances in meters](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc); the bounds are consistent with a meter-authored station. `PHYSICAL_ASSET_SCALE = 1.0` preserves that dimensional validation. The difference can include bounding-box orientation and model extent; it is not treated as an orbital or hardware measurement.

Earth View uses `DISPLAY_ENHANCED_SCALE`: **the rendered ISS is NOT TO SCALE**. Cesium `Model.minimumPixelSize = 72` aims to keep the silhouette legible as the camera retreats, while `Model.maximumScale = 20000` bounds enlargement to at most 20,000 times the 1.0 physical asset scale. These are presentation parameters, not physical dimensions. At close distance, the minimum pixel rule ceases to enlarge the model. At medium distance it increases apparent size toward 72 pixels; at global distance the upper scale bound may prevent reaching 72 pixels. The sampled WGS84 position, altitude, and orbital path do not change. [Cesium documents both sizing controls and their relationship](https://cesium.com/learn/cesiumjs/ref-doc/Model.html).

Cesium converts the asset's glTF axes for rendering, then places it at the backend-sampled ITRF position using `Transforms.eastNorthUpToFixedFrame`. The explicit static `MODEL_ASSET_ALIGNMENT` is **identity**. A small display-only translation centers the asset's off-origin bounds on the sampled point so that the camera pivots around the station. This does not shift the orbital coordinate. The resulting pose is **`DISPLAY_ONLY_LOCAL_ENU`**. `ATTITUDE = UNAVAILABLE`: no verified station attitude source or frame convention is present. The model is not aligned to orbital velocity, LVLH or the Sun. Solar-array nodes keep the source asset pose and are not animated.

The marker/path Entity and the model primitive use one `SampledPositionProperty(ReferenceFrame.FIXED)` from the same accepted REST window. Each tick reads that property; no second propagation, orbit or attitude path exists. The model remains visible at valid camera distances once ready. An unobtrusive `ISS` label and point locator accompany it beyond 2,000 km and disappear inside 1,500 km, with hysteresis to avoid flicker. The point also appears while loading or after model failure. Model loading, readiness and failure are independent of orbital delivery; an expired sample window hides both. [ISS Inspection Mode](iss-inspection-mode.md) uses the same scene and a moving ENU camera pivot. Its close zoom factor is **0.01**; Earth Overview restores 5.

Earlier browser checks at 843 × 885 on 2026-09-29 compared `maximumScale` values 5,000, 15,000 and 20,000, and `minimumPixelSize` values 48 and 72. With the final 72/20,000 setting, the global model remained a distinct roughly 50-pixel ISS silhouette on a roughly 410-pixel Earth disk, without obscuring a broad region. In a regional/orbital view it remained identifiable at roughly 50–60 pixels. The current inspection entry is at 340 m, with bounded display size; camera motion never changes the sampled orbital state. These are visual checks, not physical measurements or a pixel-accuracy contract.

The full machine-readable [`iss-model-inventory.json`](iss-model-inventory.json) records each node index, exact source name, parent, mesh name and materials. The runtime GLB itself is the geometry source. The manifest pins the runtime hash so mapped indices cannot silently point into a different file.

Only these exact NASA asset node labels are mapped at this milestone:

| Node index | Exact asset label | MISSION1 component ID | Status and evidence |
| ---: | --- | --- | --- |

| 84 | `27 Columbus Space Laboratory` | `COLUMBUS` | `VERIFIED`: explicit NASA model node name |
| 95 | `26 Harmony Node 2` | `HARMONY` | `VERIFIED`: explicit NASA model node name |

There are **no `PARTIALLY_VERIFIED` mappings**. All remaining node indices are **`UNMAPPED`** in the application, including generic geometry and historical parts. `VERIFIED` here certifies only that the named model geometry corresponds to the named component in this NASA asset; it does not certify 2026 configuration, telemetry or pose. Runtime tests assert every mapped index/name and the full inventory hierarchy against the shipped GLB.

### Picking investigation and selected approach

**Original WebP asset classification: `ENTITY_ONLY_PICKING`. Strategy: `DIRECT_FEATURE_PICKING`.** The pinned base GLB used only `EXT_texture_webp`; it had no `EXT_mesh_features`, `EXT_structural_metadata`, or feature IDs. A temporary probe on the actual Cesium 1.145 Earth View called `Scene.pick` on the visible NASA model. Geometry hits returned a plain pick object with `id: "ISS_MODEL_PICK_PROBE"`; empty-space clicks returned `undefined`. Hits had no public glTF node name, mesh identity or feature ID. [`Model.getNode(name)`](https://cesium.com/learn/cesiumjs/ref-doc/Model.html) gives programmatic node access, not screen-space node picking. [`Scene.pick`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html) and [`ModelFeature`](https://cesium.com/learn/cesiumjs/ref-doc/ModelFeature.html) provide the public screen-space path once feature metadata is present. Private Cesium fields are not used by production selection.

The reproducible script [`add-verified-module-features.py`](../../frontend/scripts/add-verified-module-features.py) tags only direct primitives of Destiny node 97 (**6 primitives**, feature ID 0/code 1), Columbus node 84 (**6 primitives**, feature ID 1/code 2), and Harmony node 95 (**4 primitives**, feature ID 2/code 3). Each mesh is used by its verified node only. Descendants are deliberately excluded: Harmony and Columbus sit below Destiny in the glTF hierarchy, and tagging a parent subtree would produce false identity. All other primitives remain untagged and `UNMAPPED`. `EXT_mesh_features` stores `_FEATURE_ID_0` per vertex; `EXT_structural_metadata` stores a three-row `moduleCode` property table. Tests verify every tagged accessor, the exact set of tagged nodes, and the runtime SHA-256. [Extension specifications](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_mesh_features) define the feature IDs and [structural metadata](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_structural_metadata).

`Scene.pick` and `Model.getNode` are documented public APIs. `Model.featureIdLabel` and `ModelFeature.featureId` are also documented public APIs, but Cesium marks their 3D Tiles feature-metadata behavior **experimental** and subject to change without its normal deprecation policy. The project pins Cesium **1.145.0**, tests the exact GLB revision and verifies picking in the browser; a Cesium upgrade must repeat that check. No undocumented/private pick fields are used.

With the derivative, actual close Earth View clicks returned `ModelFeature` IDs **0/1/2** and `moduleCode` values **1/2/3**, resolving respectively to Destiny, Columbus and Harmony. Untagged station geometry returned the plain model pick object or no hit and never resolved to a verified module. Production `Model.fromGltfAsync` sets `featureIdLabel: "missionModule"` and `enablePick: true`; the click handler uses only public `Scene.pick`, `ModelFeature.featureId`, and `ModelFeature.getProperty`. It requires both ID and code to match the pinned manifest. Module selection is enabled only within **1,000 m** camera-to-sampled-center distance, where the geometry is inspectable; global distance selects no module. Feature picking uses the same rendered Cesium model and therefore remains aligned with its `minimumPixelSize`/`maximumScale` display enhancement without a separate pick proxy or orbital coordinate calculation. Occluded module surfaces or very small visible facets may yield no selection; they never fall back to guessed spatial association. A click on empty or unmapped geometry clears the panel.

The pre-inspection production preview was tested in-browser at 1280 × 720. At the former close focus and at a slightly wider view, direct clicks selected all three named modules. Clicks on a solar array, truss, another unmapped part and empty space left no module selected. Earth overview cleared a previous selection. A closer test found some facets returned no feature because foreground unmapped geometry or gaps occupied those pixels; there was no incorrect verified selection. In the new moving inspection camera, development browser clicks again selected Destiny, Columbus and Harmony from visible feature surfaces. Module picking is intentionally surface-specific and may require a clear view of the named mesh.

The panel shows only the verified name, exact NASA source node identity, source link, historical-configuration caveat, `NOT TO SCALE` display notice, and **“Live module telemetry: unavailable”**. Selection issues no module/API request. The panel does not treat static asset naming as current onboard telemetry.

## Local performance observations

In a local browser smoke test on 2026-09-29, the UI measured approximately **0.2 s** from `Model.fromGltfAsync` start to Cesium `readyEvent` in development and **0.4 s** in Vite's served production build. These are warm local browser observations, not network or GPU benchmarks. The earlier 15,175,080 B WebP base model returned HTTP 200 from the production preview. The current semantic derivative is **15,269,472 B**, with its exact hash pinned in the manifest and verified by automated tests. The model contains roughly 247,547 triangles at close range. Loading is asynchronous and does not block the orbital marker, path or status panel. Temporarily withholding the development GLB produced `3D model: FAILED` while the near ISS marker and orbital path stayed visible; the original hash was restored afterward.
