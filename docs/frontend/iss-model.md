## Elevated Inspection and rendering stability — 2026-10-01

The current canonical desktop camera uses a **90 m slant range**, **42.5° rear elevation**, zero lateral offset and **100° FOV**. Its trajectory-frame offset is calculated as `(-90 cos(42.5°), 0, 90 sin(42.5°))`, approximately **(−66.354960, 0, 60.803119) m**. Scale remains 1 and Overview minimumPixelSize remains 80. Narrow aspect ratios widen the range by `max(1, 1.2/aspect)` while retaining elevation. Orbital details stay collapsed through entry, Inspection and return, and remain keyboard-accessible. They reopen only after the Earth pose is restored, keeping the left solar array visible during close departure.

Entry takes **6 seconds**, return **5 seconds**. The inspected strict Cartesian-speed candidate was rejected because almost all close-up growth occurred in its final frame. Its cubic geometry, 8192-segment arc-length measurement and displayed-target correction remain. Timing now inverts a normalized hybrid metric: **20% log lens distance + 60% inverse lens distance/apparent scale + 20% viewing-direction travel**. Lens distance is displayed-target range times `tan(FOV/2)`. A 1024-interval monotone C1 Hermite inverse is built once; a C2 clock has 10% start/stop rate ramps and a uniform central 80%. No scene projection or table construction runs per frame. Physical speed intentionally varies. FOV completes its change during far travel and remains 100° in the close view. Lift/silhouette follow the same path range (100–1,000 km), with camera aim following the actual displayed target. Partial Back starts at the current actual pose and retains incoming world velocity, quaternion and FOV derivatives over a range-bounded interval of at most 0.4 seconds. Earth world pose, FOV, near/far, transform and controller state restore exactly. OEM unavailability immediately selects physical GP; a shared camera/model display translation settles over 0.8 seconds during return, never changing samples, readouts, velocity or trajectories. The stable Inspection pivot remains physical. [Perceptual traces, actual raster footprints, reversals and separate performance comparison](camera-transition-perfecting-review/perceptual/README.md).

The default Cesium environment-map invalidation at every 1 km caused repeated draw-command/shader regeneration as orbital motion and 75 km display lift changed the model translation. Generate that approximate ambient environment once, retaining its full diffuse/specular maps; position/time invalidation tolerances are infinite. Direct Sun, Earth lighting, terminator and historical city imagery continue to follow scene UTC. Ambient reflections are a stable visualization approximation, not an ISS radiometric simulation. A public CustomShader filters unresolved normal variance into bounded specular roughness; source base colors, metallic factors, normal maps and PNG bytes remain inputs. MSAA 4 remains active; complementary FXAA reduces thin-edge outliers during entry, Inspection and exit, while Overview keeps MSAA alone on supported hardware. All modes retain native DPR resolution. The public silhouette width/alpha stay at imperceptible positive floors (1e-6 px / 1e-12) in Inspection so Cesium can retain a valid compiled pipeline; the visible outline is zero. Back-face culling is restored there. Overview still uses 0.5 px / alpha 0.12. Ground fog is confined below 100 km (with compensated ground density), avoiding the model shader rebuild at Cesium's default 800 km ceiling. Close-view atmospheric shaders warm during model loading. A retained native-resolution FXAA stage uses a uniform bypass in Overview, so changing modes does not destroy/reallocate its GPU resources. No asset, geometry, source contract, low-resolution LOD or texture reload is introduced.

## Runtime derivative and validation

The original VTAD GLB is available from the NASA resource page at [NASA's direct `ISS_stationary.glb` URL](https://assets.science.nasa.gov/content/dam/science/psd/solar/2023/09/i/ISS_stationary.glb). The current runtime file is [`frontend/public/models/iss-vtad-source-png.glb`](../../frontend/public/models/iss-vtad-source-png.glb), **32,735,516 B**, SHA-256 `ce23515c6bf4a77d3bac6b7c2554e3c92e137c11c8db3ee1ffc1f3ef2030a16f`. Its NASA source hash and runtime revision are pinned in [`issModelManifest.json`](../../frontend/src/cesium/issModelManifest.json). The original 44.5 MB file is intentionally outside the repository. No Git LFS or runtime NASA request is needed.

Reproduce the derivative with glTF Transform CLI **4.5.1**, using its normal CLI installation from npm and the direct GLB download exposed on the NASA page:

```sh
gltf-transform dedup ISS_stationary.glb iss-dedup-png.glb
shasum -a 256 ISS_stationary.glb iss-dedup-png.glb
python3 frontend/scripts/add-verified-module-features.py iss-dedup-png.glb frontend/public/models/iss-vtad-source-png.glb
shasum -a 256 frontend/public/models/iss-vtad-source-png.glb
```

The 32,197,496 B deduplicated PNG base derivative has SHA-256 `ce2548b56741ee764de7e1d593f1c50785a54150ebc500ed5424a4f5bdf8f657` and is the strictly pinned input to the feature-metadata script. The current runtime file retains **132 nodes, 131 meshes, 343 primitives, 325,374 vertices, 247,547 triangles and the original bounds**, with 19 embedded lossless PNG images after deduplication. The original GLB has 26 PNG entries, 19 unique images, all 512² or 1024²; the deduplicated source preserves their pixels. Four authored materials include normal maps and all source alpha channels are opaque. The script appends metadata and one sampler policy without editing geometry, materials, node transforms or texture bytes. It uses `EXT_mesh_features` and `EXT_structural_metadata`, which [CesiumJS supports](https://cesium.com/learn/cesiumjs/ref-doc/Model.html). The sampler requests linear magnification and trilinear minification with mipmaps; the GLB does not embed a precomputed mip chain. The runtime GLB file is about 32.7 MB, **not measured GPU memory**; decompressed textures, mip levels and draw resources add memory.

The original NASA file passed Khronos **glTF Validator 2.0.0-dev.3.10** with **0 errors, 17 warnings and 37 informational messages**. The PNG semantic derivative passed with **0 structural errors** under glTF Transform CLI 4.5.1 validation on 2026-09-29; pre-existing tangent-space and degenerate-triangle warnings remain. This validator reports the two feature extensions as unsupported for extension-specific validation; Cesium 1.145 browser picking is checked separately. No geometry was rebuilt. Production build must contain the GLB at `dist/models/iss-vtad-source-png.glb` with the manifest hash.

## Scale, axes and presentation semantics

[NASA describes the ISS as about 109 m across its solar arrays](https://www.nasa.gov/reference/international-space-station/). The asset's longest measured bounding dimension is **111.988 model units**, 2.99 m or **2.74%** above that approximate NASA span. [glTF 2.0 defines linear distances in meters](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/Specification.adoc); the bounds are consistent with a meter-authored station. `PHYSICAL_ASSET_SCALE = 1.0` preserves that dimensional validation. The difference can include bounding-box orientation and model extent; it is not treated as an orbital or hardware measurement.

Earth View uses `DISPLAY_ENHANCED_SCALE`: **the rendered ISS is NOT TO SCALE**. Cesium `Model.minimumPixelSize = 80` aims to keep the silhouette legible as the camera retreats, while `Model.maximumScale = 20000` bounds enlargement to at most 20,000 times the 1.0 physical asset scale. These are presentation parameters, not physical dimensions. At close distance, the minimum pixel rule ceases to enlarge the model. At medium distance it increases apparent size toward 80 pixels; at global distance the upper scale bound may prevent reaching 80 pixels. The sampled WGS84 position, altitude, and orbital path do not change. [Cesium documents both sizing controls and their relationship](https://cesium.com/learn/cesiumjs/ref-doc/Model.html).

Cesium's glTF conversion gives the verified runtime model +X forward and +Z up. The shared `TrajectoryVisualFrame` uses selected physical ITRF position/velocity at scene UTC: Forward along velocity, Left, and orthogonalized WGS84 Up. Asset-centering translation places the off-origin bounds at the separate model display point. Overview adds the **75 km display-only WGS84-normal lift**; entry removes it over the path's 1,000→100 km range and return restores it over 100→1,000 km. Camera composition follows the displayed target, while reported position, altitude, velocity and trajectories remain physical. Stable Inspection has zero lift and a physical selected-source pivot. Orientation is **`TRAJECTORY_ALIGNED_VISUAL_ORIENTATION`**, never verified onboard attitude. `ATTITUDE = UNAVAILABLE`; solar-array nodes retain the authored asset pose and are not animated.

The locator, readout, route and pivot evaluate one selected bounded `SampledPositionProperty(ReferenceFrame.FIXED)`: the mandatory GP computed buffer or separately covered NASA predicted OEM property. Each tick evaluates the source at the same scene time. Only model/camera presentation uses lift and the temporary 0.8-second display translation on OEM loss; source samples are never blended. The ready model is the sole visible ISS target; loading/failure uses the locator when position is valid, and expired data hides both. [ISS Inspection Mode](iss-inspection-mode.md) uses the current 6-second perceptual approach to 90 m / 42.5° / 100° and 5-second return. Physical asset scale stays 1, minimumPixelSize 80. Station orbit remains native; scoped proportional wheel/pinch zoom avoids globe-rate semantics and restores the captured Overview controls.

Earlier browser checks at 843 × 885 on 2026-09-29 compared `maximumScale` values 5,000, 15,000 and 20,000, and `minimumPixelSize` values 48 and 72. With the final 72/20,000 setting, the global model remained a distinct roughly 50-pixel ISS silhouette on a roughly 410-pixel Earth disk, without obscuring a broad region. In a regional/orbital view it remained identifiable at roughly 50–60 pixels. The inspection approach now passes through a 60 km station vicinity before arriving at 340 m, with bounded display size; camera motion never changes the sampled orbital state. These are visual checks, not physical measurements or a pixel-accuracy contract.

### Picking investigation and selected approach

**Original untagged asset classification: `ENTITY_ONLY_PICKING`. Strategy: `DIRECT_FEATURE_PICKING`.** The previous pinned WebP base GLB had no `EXT_mesh_features`, `EXT_structural_metadata`, or feature IDs. A temporary probe on the actual Cesium 1.145 Earth View called `Scene.pick` on the visible NASA model. Geometry hits returned a plain pick object with `id: "ISS_MODEL_PICK_PROBE"`; empty-space clicks returned `undefined`. Hits had no public glTF node name, mesh identity or feature ID. [`Model.getNode(name)`](https://cesium.com/learn/cesiumjs/ref-doc/Model.html) gives programmatic node access, not screen-space node picking. [`Scene.pick`](https://cesium.com/learn/cesiumjs/ref-doc/Scene.html) and [`ModelFeature`](https://cesium.com/learn/cesiumjs/ref-doc/ModelFeature.html) provide the public screen-space path once feature metadata is present. Private Cesium fields are not used by production selection.

The reproducible script [`add-verified-module-features.py`](../../frontend/scripts/add-verified-module-features.py), revision 2 (manifest-driven), reads only `VERIFIED` entries from the runtime manifest. It preserves Destiny/Columbus/Harmony feature IDs **0/1/2** and appends IDs **3–13**. Each tagged mesh has one owning node; only direct primitives are tagged. Descendants are excluded, so a parent node cannot claim a different named component. All other primitives remain untagged. `EXT_mesh_features` stores `_FEATURE_ID_0` per vertex; `EXT_structural_metadata` stores a 14-row `moduleCode` property table. Tests check every tagged accessor and exact tagged-node set. [Feature IDs](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_mesh_features) and [structural metadata](https://github.com/CesiumGS/glTF/tree/3d-tiles-next/extensions/2.0/Vendor/EXT_structural_metadata) are extension specifications.

`Scene.pick` and `Model.getNode` are documented public APIs. `Model.featureIdLabel` and `ModelFeature.featureId` are also documented public APIs, but Cesium marks their 3D Tiles feature-metadata behavior **experimental** and subject to change without its normal deprecation policy. The project pins Cesium **1.145.0**, tests the exact GLB revision and verifies picking in the browser; a Cesium upgrade must repeat that check. No undocumented/private pick fields are used.

The original three-feature derivative was browser-verified with `ModelFeature` IDs **0/1/2** and `moduleCode` values **1/2/3**. The expanded derivative preserves those values and adds 11 direct feature identities. Untagged station geometry returned the plain model pick object or no hit and never resolved to a verified module. Production `Model.fromGltfAsync` sets `featureIdLabel: "missionModule"` and `enablePick: true`; the click handler uses only public `Scene.pick`, `ModelFeature.featureId`, and `ModelFeature.getProperty`. It requires both ID and code to match the pinned manifest. Module selection is enabled only within **1,000 m** camera-to-sampled-center distance, where the geometry is inspectable; global distance selects no module. Feature picking uses the same rendered Cesium model and therefore remains aligned with its `minimumPixelSize`/`maximumScale` display enhancement without a separate pick proxy or orbital coordinate calculation. Occluded module surfaces or very small visible facets may yield no selection; they never fall back to guessed spatial association. A click on empty or unmapped geometry clears the panel.

The pre-inspection production preview was tested in-browser at 1280 × 720. At the former close focus and at a slightly wider view, direct clicks selected all three original modules. Clicks on a solar array, truss, another unmapped part and empty space left no module selected. Earth overview cleared a previous selection. A closer test found some facets returned no feature because foreground unmapped geometry or gaps occupied those pixels; there was no incorrect verified selection. Module picking is intentionally surface-specific and may require a clear view of the named mesh.
