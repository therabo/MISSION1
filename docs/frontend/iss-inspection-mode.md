# ISS Inspection Mode

The Earth View and the cinematic inspection view share one Cesium Viewer, scene clock, ISS Entity, and backend-derived `SampledPositionProperty(ReferenceFrame.FIXED)`. The visualization is an external presentation of computed GP/TLE propagation, **not a live ISS camera feed or onboard position measurement**.

## Modes and entry

`EARTH_OVERVIEW` keeps ordinary globe navigation, the bounded computed orbital path, and the far ISS label/point locator. A click on the visible ISS Entity, point, model or feature, or the **Inspect ISS** button, begins `ENTERING_INSPECTION` only when the detailed model and sampled buffer are ready. Cesium's `LEFT_CLICK` event distinguishes a click from a camera drag. A verified module hit in Overview enters inspection; module selection begins once the close view is available. Model failure leaves the point locator and Earth View usable but disables detailed entry.

Entry has two visible phases. First, `Camera.flyToBoundingSphere` flies in world coordinates for **3.6 seconds** toward a position read from the existing bounded `SampledPositionProperty` at the expected arrival time, stopping **60 km** from the station. Cesium's documented `EasingFunction.QUADRATIC_IN_OUT` shapes that flight. The camera starts from the actual Overview pose and the globe stays visible as it travels. The future target is interpolation of backend samples, never a new orbital propagation. If the future point is outside the sample window, entry does not begin.

Development browser trials compared **2.8, 3.6 and 4.4 seconds** for this world-space leg. The 2.8-second leg compressed the globe-to-target travel; 4.4 seconds delayed the close-up unnecessarily. The selected 3.6-second leg preserved visible Earth context while keeping entry responsive. The 1.8-second close leg was held constant in these comparisons.

The **1.8-second** close phase begins from the camera's actual arrival pose. Each tick reads the moving station position from the same sampled property and uses `Camera.lookAt` with smooth heading/pitch and logarithmic range interpolation toward heading **35°**, pitch **−10°**, range **340 m**. It then hands the current local offset to `Camera.lookAtTransform` for ISS-centered tracking. The starting close pose is taken from the actual world camera to avoid a jump at the phase boundary; the end pose is the inspection tracking pose. The Overview camera world position/direction/up are saved for return. The initial composition centers the ISS with Earth's curved limb low in frame and Cesium's star skybox behind it. Cesium's real scene Sun stays enabled and is never moved or duplicated. The normal atmosphere remains. This composition changes with viewport and orbital time.

## Moving pivot and interaction

`ISS_INSPECTION` uses `Transforms.eastNorthUpToFixedFrame` and the public `Camera.lookAtTransform` API. On each existing Cesium clock tick, the camera retains its **current local offset** while the ENU origin moves to the current sampled ISS position. This keeps the rendered station at the orbit pivot and preserves user changes to angle and range. The implementation evaluated `Viewer.trackedEntity`, but browser testing showed an incoherent close model composition after its tracking update; the explicit ENU transform gave stable model rendering and unrestricted orbit input. There is no second render loop, browser orbit propagation, or per-frame API request. A new same-lineage or new-TLE sample window replaces the position property atomically; the camera reads the new property without blending unrelated TLE lineages. A real discontinuity may therefore remain visible.

The user can drag around the station and wheel or pinch to zoom. Cesium's close-view zoom factor is **0.01**; Overview restores 5. The inspection camera retains its current local ENU offset while following the moving ISS and bounds a long-drag excursion to **2,000 m** so an input gesture cannot strand the view at a globe-sized range. The model's off-origin bounds receive a small display-only centering translation so the station, rather than an empty nearby point, is the visual pivot. The asset's physical scale remains 1 and its bounded display enlargement remains **NOT TO SCALE**. Orbital position, altitude and path are unchanged. `CAMERA TRACKING FRAME = ENU` is a navigation choice. `MODEL DISPLAY ORIENTATION = DISPLAY_ONLY_LOCAL_ENU` and `SPACECRAFT ATTITUDE = UNAVAILABLE` are separate facts; ENU is never claimed as real ISS attitude.

The 2026-09-29 development browser regression exercised the two-phase approach, repeated entry, mouse orbit, and inward/outward wheel zoom. Outward zoom increased inspection range while the station stayed the pivot. Touch orbit and pinch remain unverified. The [model record](iss-model.md#expanded-browser-acceptance-2026-09-29) records the preceding semantic milestone's picking regression.

The path and far locator hide during Inspection and return in Overview. Direct `ModelFeature` picking selects the 14 hash-bound `VERIFIED` identities in the [semantic map](iss-semantic-map.md), including Destiny, Columbus and Harmony with unchanged feature IDs. Other geometry stays `UNMAPPED`; empty or unmapped clicks clear selection. The information panel separates geometry identity from current configuration, explicitly marks Pirs as removed in 2021, and states **“Live module telemetry: unavailable.”** Occluded or very small tagged surfaces may not yield a feature hit.

## Return and failure

**Back to Earth View** works during either entry phase or after arrival. It cancels an active camera flight, clears selection, resets the camera to the world transform with `Camera.lookAtTransform(Matrix4.IDENTITY)`, and flies over 1.2 seconds to the saved Overview position and orientation. The orbital clock and API polling continue. Repeated entry/exit uses the same Viewer and listeners. A failed API refresh preserves valid buffered motion and shows delivery degradation separately from orbital quality. Once the buffer expires, the ISS position becomes unavailable, or the model fails, inspection cancels and returns safely to Overview; motion never extrapolates past the valid sample range. The model is a historical NASA VTAD visual reference and does not certify exact current hardware configuration.

The Earth in Overview, approach and Inspection uses [scene-time solar lighting and NASA's 2016 Black Marble night imagery](earth-visualization.md). Cesium's scene Sun, globe and clock drive the day/night terminator and layer fading. The imagery is historical visualization data, not live urban telemetry. The moving camera's ENU navigation frame remains separate from unavailable spacecraft attitude: **`CAMERA FRAME != ISS ATTITUDE`**.
