## Focus model

The accepted cubic/Earth-clear geometry, 8192-segment length measurement, 1024-interval C1 inverse, 20% log lens + 60% inverse lens + 20% local-direction metric, and C2 clock remain. Position and focus have separate paths.

Earth focus is the positive principal-ray point captured from the actual Earth camera: `camera + direction * max(1, -dot(camera, direction))`. This is the nearest point on the forward principal ray to Earth's centre, preserving arbitrary geographic/pitch composition rather than forcing Earth's centre. ISS focus at Inspection is the actual displayed selected-source station. Intermediate focus is a presentation point on a spherical rail about the current camera, with positive geometrically blended focal radius. It is not an ephemeris point or spacecraft attitude.

The rail connects captured Earth orientation and the selected-frame close orientation. Return captures the actual orbited/zoomed orientation in the current frame and ends at the exact saved world orientation. A fixed quaternion branch at capture avoids choosing opposite rails when a moving frame crosses a 180° composition. The close orientation follows current selected-source F/L/U, while Earth orientation remains captured in world coordinates. Cesium 1.145 `Camera.setView` converts Direction/Up through local ENU heading/pitch/roll. Its `EPSILON3` nadir branch drops roll and changes the heading rule when `abs(localDirection.z)` lies within 0.001 of one (about a 2.56° cone). A browser probe proved a 1.43° requested/applied-ray difference and a roughly 501 km focal recapture jump. Automatic motion now copies the orthonormal basis into the public Camera position/direction/up/right fields under identity transform, avoiding that conversion; native navigation remains unchanged. See the [public Camera fields](https://cesium.com/learn/cesiumjs/ref-doc/Camera.html) and the pinned installed `@cesium/engine/Source/Scene/Camera.js` methods `directionUpToHeadingPitchRoll`, `getHeading`, `getRoll`, `setView3D`. Camera remains world-coordinate throughout automatic motion; the local transform is adopted only at the exact Inspection endpoint.

The normalized rail budget is `clamp(0.25 + 0.3 * capturedBasisAngle/pi, 0.3, 0.5)`. Entry spends that initial fraction of the existing hybrid metric on focus transfer; return spends the final fraction. Each applies the existing integrated C2 rate clock. `focusBlend` is explicit and monotone; no discrete ownership switch occurs.

A plain spherical rail was rejected after side/limb/pitch browser tests lost the station. The retained smooth angular containment measures rail-to-displayed-ISS error `theta` and replaces it with `theta / (1 + (theta/limit)^8)^(1/8)`, where `limit = 0.25 * min(capturedFOV, EarthFOV)`. A C2 envelope across the first/last 5% of hybrid progression preserves arbitrary endpoint compositions. The minimal corrective rotation transports the entire Direction/Up basis without injecting roll. The focal point follows the corrected ray; no independent residual quaternion fights the focal direction. Focus is always in front and at least one metre from the camera. The baseline lacked an explicit focal point; its nominal target and residual aim are analyzed separately, without inventing baseline focus coordinates.

Presentation continuity is C1, with C2 clocks/envelopes and endpoint ramps. The retained inverse is C1, so global C2 acceleration is not claimed. Physical source positions retain their bounded degree-one interpolation and its sample-knot derivatives. Partial Back captures focal radius and world focus velocity along with actual world pose/quaternion/FOV derivatives, using the existing bounded tangent interval. The positive radius is recomputed after pose tangents, ensuring focus and direction agree. The retained focal derivative is the coherent product derivative `cameraVelocity + radiusRate*direction + radius*(angularVelocity × direction)` using the same measured pose rates retained by Back. Independently differencing the product over a curved, finite frame interval would introduce incompatible transverse estimates. Raw point-to-point focus velocities and acceleration differences are reported separately in the frame audit. No physical source sample, velocity, readout or trail is blended.

Duration is captured once: base 6s entry /5s return + `0.35*ln(EarthRange/16,573,499)` + `0.4*max(0,directionChange-pi/2)`, rounded to 0.1s and bounded to 4–7.5s entry /3.5–7.5s return. Canonical endpoints keep 6/5s, 90m /42.5° /100°. Close and far starts adapt without changing the accepted close-range progression.

## Resource preparation

One Viewer owns one model/custom PBR shader, globe/ellipsoid terrain, atmosphere/fog, skybox, retained FXAA stage and source trails. The GLB preloads all embedded textures without streaming. Model texture/semantic readiness is critical. The now-ready model may render during graphics warmup while Inspect stays disabled; loading/error locator behavior remains available. Failure cancels warmup and removes the temporary reveal permission.

Startup prepares zero-imagery and textured low-altitude globe atmosphere variants in four renders, restores public imagery alpha and fade fields, then submits four additional normal-quality model/PBR/silhouette/FXAA/environment renders before enabling Inspect. A separately scheduled startup idle task also submits the retained Moon and Sun draw commands from temporary public camera views, then renders the exact captured Earth view, restoring transform, basis, far plane, input lock and render loop. This avoids a reproduced lazy Moon ellipsoid-program compile at 11% of a rotated-globe entry (72.5 ms; 171.6 ms in a dense diagnostic with the actual shader sources). It uses public Simon1994/Transforms celestial display functions consistent with Cesium, not any ISS telemetry or attitude. The model and sky preparation gates must both complete. Model counting waits for the sky task, so its temporary views cannot satisfy the eight-frame preparation gate when a cached GLB wins the startup race. A forced six-second idle delay exercises this ordering in both builds. Existing Moon/Sun objects, textures and shader quality are retained; no extra scene or private shader binding is used. [Public planetary positions](https://cesium.com/learn/cesiumjs/ref-doc/Simon1994PlanetaryPositions.html), [Viewer render lifecycle](https://cesium.com/learn/cesiumjs/ref-doc/Viewer.html). Native DPR, full textures and authored materials remain. Providers/layers and their caches are retained during warmup. Optional GIBS probes/downloads and optional skybox replacement do not block the model gate indefinitely; local day/night and default sky remain fallbacks. No terrain download exists: terrain is WGS84 ellipsoid. Newly encountered imagery LOD/network availability remains scene-dependent and is not promised as fully prefetched global coverage.

Transition construction captures geometry, focal parameters and LUT once (measured separately as preparation cost). Automatic camera evaluation reuses vectors, matrices and quaternions. It allocates no focal arrays, LUTs, material, primitive, controller or React camera state per frame. Mode callbacks occur at boundaries; scene time/readout reporting stays throttled. Rendering work remains GPU-heavy at native DPR2; no universal 60FPS claim is made.

## Reproduction

Use Node24, Python/Pillow/NumPy/matplotlib and Playwright Chromium with ANGLE Metal. `scripts/instrument-focus.py` rejects Git-managed checkouts and extends the previous archive-only hook. Create separate `git archive` copies of baseline/frontend and candidate/frontend, link installed node_modules, instrument only those copies, and run dev/preview on separate ports. Runtime fixtures are real archived backend outputs from `inspection-orientation-review`, labeled diagnostic inputs; they are never production fallbacks.

`scripts/run-qa.cjs` serializes Chromium workloads. `trace-focus.cjs` captures every rendered frame, first/fresh and second/warm entry/return, focal/pose/projection/presentation and CPU timings, native GL calls and CPU profiles. `arbitrary-focus.cjs` uses actual retained scene renders at 101 explicit progress samples plus 2001 numerical samples per path; frozen-clock geometry checks are separate from real-time pacing. `focus-reversals.cjs` measures real captured incoming/outgoing pose and focus derivatives at seven Back fractions. The adapted prior matrix/regression runners cover lighting, navigation, semantic picking, loading, source loss and responsive layouts. Ten-cycle real-time runs and raster captures are recorded separately.

Raw PNG model/background pairs remain disposable; native-pixel measurements and readable JPEG/contact-sheet evidence are retained. No videos are needed. [Results and acceptance](results.md) distinguish failures/rejected trials, final numerical/visual gates, performance limits and publication.
