# Diagnostic reproduction

These are review probes, not application runtime. They operate through public Cesium objects plus a temporary diagnostic getter. Production contains no `__qa` hook, shader override, texture-upload wrapper or synthetic orbital input.

Use Node 24, an existing Playwright installation with Chromium, and Python with NumPy/Pillow. Set `MISSION1_PLAYWRIGHT_MODULE` to an absolute installed Playwright module if it is not resolvable normally. `MISSION1_REPO_ROOT` points at the repository containing the real captured fixtures; `MISSION1_EVIDENCE_DIR` selects a temporary output folder (default `/tmp/mission1-rendering-evidence`). No dependency is added to the application.

1. Create two disposable archives of the `frontend` directory, one at baseline `4d3902989e64f0372eacea15f4efeca795f05a0e`, one at the final committed revision. Keep their dependencies identical to the lockfile. They can reuse an existing compatible `frontend/node_modules` through a symlink.
2. Run `python3 instrument-qa-copy.py ARCHIVE_ROOT` on each archive. It refuses a checkout containing `.git`. Build each archived frontend and serve baseline on 4174 and candidate on 4173; serve candidate development on 5173 for the full QA.
3. Run `node rendering-profile.cjs 4174`, then `node rendering-profile.cjs 4173` **sequentially**. Both use the identical viewport, DPR, recorded real source responses, initial UTC/camera and controlled imagery fallback. Keep unrelated GPU/CPU jobs closed during measurement. Baseline Julian-time transitions require 1× UTC motion; static windows pause it. Profiling captures allocate observation records equally in both builds; production camera evaluation uses retained objects.
4. Run `full-rendering-qa.cjs 5173` and `4173`, followed by `extra-rendering-qa.cjs` for those ports. These cover the lighting epochs, camera trial matrix, interruptions, disclosure, touch pinch, all 14 feature picks, refresh, delayed model and unavailable OEM. Extra QA changes only its routed response when testing an outage.
5. `sampler-probe.cjs` records WebGL uploads/samplers; `rendering-quality-cost.cjs` compares shader/FXAA costs; `aa-stage-cost.cjs` alternates enabled/disabled stage windows with fixed materials and pose, and captures the final motion series. `material-probe.cjs` runs the original/flat-normal/rough/specular-AA/FXAA controls. `flicker-probe.cjs` isolates station-motion environment regeneration. `occupancy-silhouette.cjs` captures visible raster footprint, frozen static pairs and on/off outline motion for both sources and two lighting epochs. Each browser probe should run alone.
6. `geometry-probe.py` audits transformed source faces for coincident geometry/winding, without modifying the GLB. Material/raster statistics count adjacent RGB-channel changes in fixed patches; expected moving geometry edges contribute, so this is not an absolute count of flicker events.

The `asset-axes.json`, `real-samples.json`, `real-comparison.json` and `phase-{0,1,2}-*.json` inputs are already archived in the preceding `inspection-orientation-review`. They are genuine captured backend responses used as offline test fixtures. No replay feature is added.

Run `statistics.py` after the image probes to produce patch/raster metrics and the diagnostic contact sheet. Run `final-live-qa.cjs` and `fallback-live-qa.cjs` against **uninstrumented** development/production builds and the actual backend; they reject an exposed diagnostic getter and check the served bundle.

Destroy the temporary archives when finished. Build/validate the uninstrumented application separately against its actual backend, including a deliberate imagery outage; retain its served bundle hash and verify no diagnostic getter is present. Cold shader/asset startup and network behavior remain distinct from warmed transition measurements.
