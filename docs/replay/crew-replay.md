# Crew effective-time reconstruction

**Normal unified lifecycle — ADR-0021 / 2026-10-12:** Replay uses V7 + S10 + the same pure V10 policy as Current, explicitly in HISTORICAL context. Operational evidence uses effective≤T and today's exact latest compatible binding; structured observations use successful capture≤T with completion committed by knowledge time, and editorial observations use acquisition completion≤T. No current roster or later capture is backdated. OBSERVED applicability is seven days inclusive; entry/departure presence implication fourteen days; counts seventy-two hours. A completed departure veto persists beyond presence freshness until a strictly later qualified operational reentry. Editorial-only supports participate in coverage. No per-T rows are persisted. Later source/binding correction may change best-current reconstruction; immutable prior rows retain their original meaning. Public status remains the existing PARTIAL_MATCH enum; modern membership metadata is `HISTORICAL_V10_S10`, revision0/age0 indicating an unpersisted evaluation. Original source and sealed binding knowledge provenance remain auditable. The earlier legacy-engine descriptions below now apply only to explicit `mission1.replay.crew.mode=LEGACY` rollback/comparison.


## Restyled responsive presentation — 2026-10-08

Historical Crew shares the restyled workspace and roster layout with Current. Pending/failed requests keep the accepted temporal context and show an explicit notice with real retry; no Current fallback is presented as historical data. Member detail stays within the bounded Crew content owner, with Back/Close reachable on compact and short-height screens. The single global Historical UTC editor bounds its date/time scroll body to the scene row and leaves Close/Cancel/Apply outside that scroll owner. Its draft, coverage validation and accepted-UTC semantics are unchanged. [Responsive inventory and real-data/TEST-ONLY QA distinction](../frontend/ui-restyling-responsive/README.md).

Structured LL2 snapshots establish assignments and Expedition context only from a retained successful capture onwards. Expedition start dates do not establish prior presence or prior observations. Select the latest retained SUCCESS/NO_ACTIVE observation captured at or before T, within the configured primary applicability window (default six hours). A new failure does not create a historical operational fact. Repeated successful capture of an unchanged body can support a new observation interval. A→B→A selection follows capture order; profile enrichment follows the latest successful capture, including reused bodies.

Filter each selected assignment by supplied validity: validFrom inclusive, validUntil exclusive. Unknown personal validity stays unknown; Expedition dates are not substituted. Explicit NO_ACTIVE clears older assignment context; absence of structured support leaves Expedition/assignment fields unavailable.

NASA operational evidence is ordered by sourceEventAt, otherwise sourcePublishedAt. A completed person entry/departure can apply before its publication or retrieval if a parsed event timestamp supports that time. Do not infer an unparsed timestamp from narrative text. Planned events, docking and hatch events do not establish person presence. Partial roster omission never establishes departure. Equal-time opposite claims or incompatible counts preserve ambiguity. Later completed transfer invalidates an older reported count without fabricating a replacement. Unresolved and ambiguous identities remain report subjects; replay never resolves identities or rewrites assertions.

The accepted pure reconciliation engine has an explicit effective-time mode. Live evaluation retains its original acquisition/fetch freshness semantics; replay uses evidence applicability at T: current/count assertions default 72 hours, completed transfer implications default 14 days from effective time. These are versioned MISSION1 limits, not provider guarantees. Expired claims can be retained as STALE last-known context when other evidence supports T, never as confirmed presence. Outside the union of usable evidence intervals Crew is UNAVAILABLE/NO_DATA, with no current roster fallback.

Counts distinguish official reported aboard, last-known official, resolved confirmed aboard, unresolved report entries, unidentified count remainder and structured assignments. Assignment != presence; LL2 in_space != aboard; planned != completed; partial omission != departure.

Profiles use **LATEST_AVAILABLE_CANONICAL_METADATA** for only the identities in the historical operational result. Names, biography, agency, nationality, media rights and cumulative career totals may be observed after T. Operational assignment/presence fields in replay profiles are effective at T, despite compatibility DTO field names currentAssignment/currentPresence. The replay UI labels these as historical and labels career totals as latest retained metadata, never elapsed Expedition time.

Coverage contains inclusive intervals, start/end, status and limitations. Crew coverage is PARTIAL even in a supported interval because current retained evidence does not prove an exhaustive roster. Gaps remain separate intervals. Structured observation provenance and every contributing NASA assertion retain original hash, source URL, retrieval, publication/event times, source version and method version. Reconciliation is query-time: reconciledAt and reconciliation attempt fields are null because no reconciliation run was created.
